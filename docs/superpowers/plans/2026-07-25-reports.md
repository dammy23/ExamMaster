# ExamMaster Reports (Phase 3e part 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring `client/src/pages/admin/Reports.tsx` in line with the rest of the overhauled admin suite — flat cards instead of gradients, `LoadingState`/`EmptyState` instead of custom spinners and silent blanks, a real green "success" status color for Passed/Failed outcomes, and dead-code/debug-log cleanup.

**Architecture:** One new design-system token (`status-success`) plus two new `StatusBadge` values (`passed`/`failed`) laid down first, since every later task in `Reports.tsx` depends on them being available. The rest of the work proceeds report-view by report-view (Exam Overview → Question Analysis → Student Scores → Performance Analysis) since that's how the page is actually navigated and tested — each view is independently selectable via the report-type dropdown and independently verifiable.

**Tech Stack:** React + TypeScript (Vite), Tailwind CSS, shadcn/ui components. No test framework exists in this repo — verification is `npx tsc --noEmit -p tsconfig.app.json` (regression check against `main`) plus manual Playwright walkthroughs, exactly as every prior phase in this overhaul has done.

## Global Constraints

- No automated test framework exists in this repo — do not introduce one. Verification is `npx tsc --noEmit -p tsconfig.app.json` (never bare `tsc --noEmit`) plus manual/Playwright checks.
- Any new `npm install` in a fresh worktree needs `PUPPETEER_SKIP_DOWNLOAD=true` set first.
- `server/.env` is gitignored and does not exist in a fresh worktree — create it before starting the dev server, with `DATABASE_URL=mongodb://localhost:27017/exammaster-dev`, a freshly generated `JWT_SECRET`, and `PORT=3000`.
- Use `http://127.0.0.1:5173` in Playwright, never `localhost`.
- Debug-log cleanup is scoped to `Reports.tsx` only — do not touch logging inside `client/src/api/reports.ts`.
- Do not touch `server/routes/reportRoutes.js` — the `/students` route stays as-is (see spec §4).
